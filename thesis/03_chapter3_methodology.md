# MATERIALS AND METHODS

## 3.1 Overview of the Proposed Methodology

The proposed system for lung cancer detection is structured as a four-phase pipeline, as
illustrated in Figure 3.1. The phases are executed sequentially, and each produces
outputs that feed directly into the next.

- **Phase 1 — Data Acquisition and Preprocessing.** Raw CT images are acquired from two
  benchmark datasets, cleaned, windowed (for DICOM data), resized and normalised into a
  uniform format ready for training.
- **Phase 2 — Transfer Learning and Feature Extraction.** Three pre-trained CNN
  architectures — EfficientNet-B0, DenseNet-121 and ResNet-50 — are fine-tuned on the
  preprocessed images using a two-phase transfer learning strategy to extract
  discriminative features for binary cancer classification.
- **Phase 3 — Stacked Ensemble Model Development.** The probability outputs of the three
  base models are used as meta-features to train an XGBoost meta-learner, combining the
  predictions of all three architectures into a single, more robust final prediction.
- **Phase 4 — Explainable AI (XAI) with Grad-CAM Visualisation.** Gradient-weighted
  Class Activation Mapping (Grad-CAM) is applied to the best-performing base model for
  each input image to produce a visual heatmap that highlights the CT regions most
  responsible for the prediction, providing clinically interpretable evidence alongside
  the classification output.

Throughout all phases, class imbalance is addressed by integrating a Conditional
Generative Adversarial Network (GAN) that generates synthetic minority-class images
during the data preparation stage. The complete pipeline is then deployed as an
interactive web application for demonstration and real-time inference.

> (pipeline diagram: Phase 1 → Phase 2 → Phase 3 → Phase 4 → Grad-CAM output)

## 3.2 Datasets

Two publicly available datasets are used to train, validate and test the proposed
system. They differ substantially in their image type, annotation style, size and
institutional origin, making the combination an effective test of both raw performance
and cross-dataset generalisation.

### 3.2.1 IQ-OTH/NCCD Dataset

The **IQ-OTH/NCCD** (Iraq Oncology Teaching Hospital / National Centre for Cancer
Diseases) dataset is a publicly available collection of lung CT images gathered from
patients attending oncology centres in Iraq. The dataset is provided as pre-processed
PNG images, organised into two top-level folders corresponding to the two classes:
*Cancer* (malignant) and *No Cancer* (benign/normal). Labels are assigned at the
patient or folder level, making the dataset straightforward to load and use in a
supervised classification pipeline.

The IQ-OTH/NCCD dataset provides a clean, well-structured benchmark: images are
already windowed, converted to standard format and free from the variability introduced
by multi-scanner, multi-institution acquisition. It has been widely used in published
studies of lung cancer classification [9, 10], and prior work has reported classification
accuracies in the range of 95–100% on this dataset, indicating that it is learnable
for modern deep learning architectures.

described in Section 3.5, is shown in Table 3.1. Synthetic images generated by the
Conditional GAN (Section 3.4.2) were added to the training split only; the validation

### 3.2.2 LIDC-IDRI Dataset

The **LIDC-IDRI** (Lung Image Database Consortium – Image Database Resource Initiative)
dataset [8] is a large-scale, multi-institutional collection of thoracic CT scans
accompanied by lesion annotations created by up to four experienced thoracic
radiologists. The full dataset contains 1,018 cases from seven academic medical centres
in the United States. For this study, 200 cases (LIDC-IDRI-0001 to LIDC-IDRI-0200) are
used, with each case contributing 10 CT slices extracted from the middle 60% of the
lung volume — a region most likely to contain clinically relevant nodules — yielding a
total of approximately 2,000 slices per class before splitting.

Unlike the IQ-OTH/NCCD dataset, LIDC-IDRI images are stored in **DICOM** format,
encoding pixel intensities in Hounsfield Units (HU). Each DICOM file includes metadata
fields for `RescaleSlope` and `RescaleIntercept` that must be applied to convert raw
pixel values to calibrated HU values before windowing (Section 3.3.2). The annotations
in LIDC-IDRI are provided as XML files; binary labels (cancer / no-cancer) are derived
from the radiologist annotations according to the labelling convention of the dataset
preparation script.

The multi-institutional origin of LIDC-IDRI introduces substantial variability in
scanner make and model, acquisition protocol, slice thickness and nodule appearance,
making it a significantly more challenging and clinically representative benchmark
than IQ-OTH/NCCD. The class distribution after splitting is shown in Table 3.2.

## 3.3 Data Preprocessing

All images, regardless of source format, are passed through a uniform preprocessing
pipeline before being used for training or inference. The pipeline is implemented in
`src/preprocessing.py`.

### 3.3.1 Image Loading and Supported Formats

The system supports three input formats: **PNG**, **JPEG** and **DICOM** (`.dcm`).

- **PNG and JPEG** images are loaded using OpenCV, converted from BGR to RGB colour
  space, and normalised to the range [0, 1] by dividing pixel values by 255.
- **DICOM** images require additional steps (described in Section 3.3.2) before they can
  be treated as standard image data.

After format-specific loading, all images are converted to a three-channel (RGB)
representation. For DICOM images, which are inherently single-channel (greyscale), the
windowed luminance channel is replicated across all three channels to produce a
compatible three-channel array. This ensures that pre-trained ImageNet weights —
which expect three-channel input — can be applied without architectural modification.

### 3.3.2 HU Windowing for DICOM Slices

Raw DICOM pixel values are first converted to calibrated Hounsfield Units (HU) by
applying the affine transformation:

```
HU = pixel_value × RescaleSlope + RescaleIntercept
```

where `RescaleSlope` and `RescaleIntercept` are extracted from the DICOM metadata
using the `pydicom` library. This calibration step ensures that pixel values are
physically meaningful and comparable across different scanners and acquisition
protocols.

A **lung window** is then applied to isolate the relevant anatomical structures and
suppress the background. The lung window is defined by:

- **Window Centre (Level):** −600 HU
- **Window Width:** 1500 HU

This corresponds to a display range of approximately −1350 HU (air) to +150 HU (soft
tissue), encompassing the full range of lung parenchyma while suppressing bone and
other high-density structures. Pixel values outside this range are clipped, and the
resulting values are linearly rescaled to [0, 1].

> **Figure 3.4** — Data preprocessing pipeline: DICOM → HU conversion → lung
> windowing → RGB replication → resize → normalise

### 3.3.3 Resizing and Normalisation

After loading and windowing, all images are resized to **224 × 224 pixels** using
bilinear interpolation. This size is standard for ImageNet pre-trained architectures
and provides a balance between spatial detail and computational efficiency.

Finally, pixel values are normalised using the **ImageNet statistics** (mean =
[0.485, 0.456, 0.406], std = [0.229, 0.224, 0.225] per channel). This is essential
for transfer learning: since the pre-trained models were trained on ImageNet-normalised
images, applying the same normalisation ensures that the learned feature representations
remain valid.

## 3.4 Data Augmentation

Data augmentation is applied during training to increase the effective size and
diversity of the training set and to reduce overfitting.

### 3.4.1 Classical Image Augmentation

Standard spatial and photometric augmentation transforms are applied on-the-fly during
training using the **Albumentations** library. The augmentation policy includes:

- **Horizontal flip** (p = 0.5)
- **Vertical flip** (p = 0.3)
- **Random rotation** (±15°, p = 0.5)
- **Brightness and contrast adjustment** (limit = ±0.2, p = 0.5)
- **Gaussian blur** (kernel size 3–7, p = 0.3)
- **Gaussian noise** (var limit = 10–50, p = 0.3)

These augmentations are applied randomly at each training epoch, so no two presentations
of the same image are identical. They are intentionally conservative (e.g. small
rotation angles) to avoid introducing unrealistic anatomical distortions that could
confuse the model or produce images inconsistent with real clinical data.

### 3.4.2 Conditional GAN Augmentation

Classical augmentation can only create variations of existing images; it cannot
generate genuinely new examples that cover unseen regions of the data distribution.
To address class imbalance — specifically the under-representation of benign cases in
the IQ-OTH/NCCD dataset — a **Conditional Generative Adversarial Network (cGAN)**
[6] is trained to generate synthetic CT images of a specified class.

A cGAN conditions both the generator and the discriminator on a class label, enabling
targeted generation of images belonging to a chosen category. Once trained, the
generator is used to produce 67 additional synthetic *No Cancer* images, which are
added exclusively to the training split to partially balance the class distribution
(see Table 3.1). The validation and test sets are never augmented.

#### 3.4.2.1 Generator Architecture

The generator (`src/gan/generator.py`) takes as input a random noise vector **z** of
dimension 100 (sampled from a standard normal distribution) and a class label. The
label is passed through a learned **embedding layer** (dimensionality 100), and the
embedded label vector is concatenated with the noise vector to form a combined input
of dimensionality 200.

This combined vector is projected by a fully connected layer to a spatial feature map
of shape 128 × 16 × 16 (i.e., 128 channels at spatial resolution 16 × 16, since the
output image size is 64 and the initial spatial size is 64 ÷ 4 = 16). The feature
map is then passed through a series of convolutional upsampling blocks:

1. **BatchNorm** → **2× Upsample** → **Conv2d(128→128, 3×3)** → **BatchNorm** →
   **LeakyReLU(0.2)** — produces 128 × 32 × 32
2. **2× Upsample** → **Conv2d(128→64, 3×3)** → **BatchNorm** → **LeakyReLU(0.2)** —
   produces 64 × 64 × 64
3. **Conv2d(64→3, 3×3)** → **Tanh** — produces the final RGB image at 3 × 64 × 64

The Tanh activation ensures that generated pixel values lie in [−1, 1], consistent
with the normalised training images.

> **Figure 3.5** — Conditional GAN architecture: generator (left) and discriminator
> (right), with class label conditioning shown

#### 3.4.2.2 Discriminator Architecture

The discriminator (`src/gan/discriminator.py`) receives an image (real or generated)
and a class label. The label is embedded into a spatial tensor of the same height and
width as the input image (64 × 64) and concatenated to the image along the channel
dimension, forming a 4-channel input (3 image channels + 1 label channel).

This combined tensor is passed through four downsampling convolutional blocks, each
consisting of **Conv2d (stride 2)** → **BatchNorm** (omitted in the first block) →
**LeakyReLU(0.2)** → **Dropout2d(0.25)**. The channel progression is:
4 → 16 → 32 → 64 → 128. After four strides of 2, the spatial resolution is reduced
from 64 to 4 (64 ÷ 2⁴ = 4). The flattened output (128 × 4 × 4 = 2,048 values) is
passed through a linear layer followed by a **Sigmoid** activation, producing a scalar
probability that the input image is real.

#### 3.4.2.3 GAN Training Procedure

The GAN is trained for **150 epochs** using the **Adam** optimiser with a learning rate
of 0.0002 and β₁ = 0.5 (the standard configuration for GAN training [6]). The batch
size is 64. At each step:

1. A batch of real images with their true labels is drawn from the training data.
2. The discriminator is updated on a mixed batch of real and generated images (binary
   cross-entropy loss).
3. The generator is updated by maximising the discriminator's probability of
   classifying its generated images as real.

The generator and discriminator losses are monitored throughout training. After
training, the generator is used in inference mode to produce the required number of
synthetic images for the target class.

## 3.5 Data Splitting Strategy

For both datasets, images are divided into **training**, **validation** and **test**
splits. The split proportions are approximately **70 % / 15 % / 15 %**, with stratified
sampling to ensure that the class ratio is consistent across all three splits.

The splitting strategy respects **patient-level boundaries** for LIDC-IDRI: all slices
extracted from the same patient are assigned to the same split, preventing data leakage
between the training and evaluation sets. This is critical for obtaining unbiased
performance estimates, since slices from the same CT volume are visually very similar
and would allow a model to "recognise" a patient it had already seen during training.

The **validation set** serves two purposes: (i) early stopping during CNN training
(Section 3.6.4), and (ii) training the XGBoost meta-learner in the stacked ensemble
(Section 3.7). Using the validation set for the meta-learner — rather than the
training set — is the key design decision that prevents data leakage in the ensemble
(see Section 3.7.1).

> **Table 3.3** — Train / validation / test split for both datasets

| Dataset | Train | Validation | Test | Total (real) |
|---|---|---|---|---|
| IQ-OTH/NCCD | 767 (+ 67 synthetic) | 164 | 166 | 1,097 |
| LIDC-IDRI | 834 | 300 | 300 | 1,434 |

## 3.6 Base CNN Models

Three CNN architectures are employed as base models in the stacked ensemble. They were
chosen for their complementary strengths: EfficientNet-B0 for parameter efficiency,
DenseNet-121 for feature reuse, and ResNet-50 for residual learning. All three are
loaded with **ImageNet pre-trained weights** and adapted for binary classification
(cancer / no-cancer, i.e. 2 output classes). The implementation resides in
`src/models/base_models.py`.

### 3.6.1 EfficientNet-B0

**EfficientNet-B0** [5] is loaded via the `timm` library (`timm.create_model(
'efficientnet_b0', pretrained=True, num_classes=0)`), which removes the built-in
classification head and returns a feature extractor whose output dimensionality is
1,280. A custom classification head is appended:

```
Dropout(0.3) → Linear(1280, 512) → ReLU → Dropout(0.3) → Linear(512, 2)
```

EfficientNet-B0 was designed using a compound scaling rule that simultaneously
optimises depth, width and resolution. With approximately 5.3 million parameters in
the backbone, it is the most parameter-efficient of the three architectures, which is
advantageous given the relatively small size of the training datasets.

> **Figure 3.6** — EfficientNet-B0 architecture with the custom classification head

### 3.6.2 DenseNet-121

**DenseNet-121** [4] is loaded via `torchvision.models` with ImageNet weights. Its
original fully connected classifier (1,024 → 1,000) is replaced with:

```
Dropout(0.3) → Linear(1024, 512) → ReLU → Dropout(0.3) → Linear(512, 2)
```

DenseNet-121's defining characteristic is its **dense connectivity**: within each dense
block, every layer receives the concatenated feature maps of all preceding layers as
input. This maximises feature reuse, reduces the vanishing gradient problem, and
produces strong gradient flow even in the lower layers — properties that are
particularly beneficial when fine-tuning on small medical datasets, as the pre-trained
low-level features are preserved effectively.

> **Figure 3.7** — DenseNet-121 architecture showing dense blocks and the custom head

### 3.6.3 ResNet-50

**ResNet-50** [3] is loaded via `torchvision.models` with ImageNet weights. Its
original fully connected layer (2,048 → 1,000) is replaced with:

```
Dropout(0.3) → Linear(2048, 512) → ReLU → Dropout(0.3) → Linear(512, 2)
```

ResNet-50 introduces **residual connections** (skip connections) that add the input of
a block directly to its output, allowing gradients to flow freely through the network
during backpropagation. This makes it possible to train very deep networks (50 layers in
this case) without the accuracy degradation that afflicts plain networks of comparable
depth. ResNet-50 has the largest feature dimension (2,048) of the three backbones,
giving it the greatest representational capacity at the cost of a larger number of
parameters.

> **Figure 3.8** — ResNet-50 architecture with residual blocks and the custom head

### 3.6.4 Transfer Learning and Two-Phase Training

All three models are trained using a **two-phase transfer learning strategy**:

**Phase 1 — Frozen Backbone (25 epochs).**
In the first phase, the pre-trained backbone parameters are frozen (`requires_grad =
False`) and only the custom classification head is trained. This allows the head to
learn an appropriate mapping from the pre-trained feature space to the binary cancer
classification task, without corrupting the carefully learned ImageNet representations.
The learning rate is set to **1e−4** with the **AdamW** optimiser (weight decay 1e−5).

**Phase 2 — Full Fine-Tuning (25 epochs).**
In the second phase, all backbone parameters are unfrozen and the entire network is
fine-tuned end-to-end. The learning rate is reduced to **1e−5** to avoid
catastrophically overwriting the pre-trained features with large gradient updates.
Training continues with the same AdamW optimiser.

**Class imbalance handling.** To address the remaining class imbalance after GAN
augmentation, class weights are applied to the cross-entropy loss function. The weights
are set to **[1.0, 2.0]** for the no-cancer and cancer classes respectively, causing
the model to penalise missed cancer cases (false negatives) more heavily than false
alarms (false positives) — a clinically appropriate choice for a screening system.

**Early stopping** with patience = 10 is applied throughout both phases, monitoring
the validation loss. If the validation loss does not improve for 10 consecutive epochs,
training is terminated and the checkpoint with the lowest validation loss is restored.
**Automatic Mixed Precision (AMP)** is used during training to halve memory usage and
accelerate computation on compatible GPUs.

> head only) → Phase 2 (full fine-tuning at lower learning rate)

## 3.7 Stacked Ensemble

The three trained base models are combined into a **stacked ensemble** [9, 16] to
produce a single, more accurate and more reliable final prediction. The implementation
resides in `src/ensemble/stacking.py`.

### 3.7.1 Out-of-Fold Predictions and Meta-Features

Stacking requires a second-level ("meta") learner to be trained on the outputs of the
base models. A critical design requirement is that the meta-learner must be trained on
**predictions made on data that the base models did not see during their own training**;
otherwise the meta-learner simply learns to trust whichever base model memorised the
training data best, producing inflated and misleading accuracy estimates.

In this system, the meta-learner is trained on the base models' **probability outputs
on the validation set** — data that was held out from base model training. Each base
model produces a two-dimensional probability vector [P(no cancer), P(cancer)] for each
validation image. Concatenating these vectors across all three models yields a
meta-feature vector of dimension **6** (3 models × 2 probabilities) per image.

This approach is clean and reproducible: no cross-validation over the training set is
required, and the meta-features are derived from genuinely unseen predictions. The
choice also reflects a lesson learned during development: an earlier version of the
system trained the meta-learner on training-set predictions, leading to near-perfect
meta-features (because the base models had already memorised the training data) and
artificially inflated ensemble accuracy. This data-leakage bug was identified and fixed
by switching to validation-set meta-features.

### 3.7.2 XGBoost Meta-Learner

**XGBoost** (Extreme Gradient Boosting) [13] is selected as the meta-learner. XGBoost
is an ensemble of decision trees trained using gradient boosting; it is robust to noisy
input features, handles non-linear relationships between base model outputs, and is
computationally efficient to train on the small meta-feature dataset (one 6-dimensional
vector per validation image). It also provides calibrated probability estimates via
`predict_proba`, which are used for the ROC-AUC evaluation of the ensemble.

The meta-learner is trained on the 6-dimensional validation meta-features with the true
binary labels. At test time, the three base models are applied to each test image,
their probability outputs are concatenated into a 6-dimensional vector, and the XGBoost
meta-learner produces the final prediction.

> outputs → 6-d meta-feature vector → XGBoost meta-learner → final prediction

## 3.8 Explainability with Grad-CAM

To make the system's predictions interpretable, **Gradient-weighted Class Activation
Mapping (Grad-CAM)** [7] is applied to the best-performing base model for each input
image. The implementation resides in `src/explainability/gradcam.py`.

**How Grad-CAM works.** Grad-CAM computes the gradient of the class score with respect
to the feature maps of a chosen target convolutional layer. These gradients capture how
much each spatial location in the feature map contributed to the final classification
decision. A **global average pooling** operation over the spatial dimensions of the
gradient tensor produces a weight for each feature map channel. The final activation
map (CAM) is computed as the **ReLU-activated weighted sum** of the feature maps:

```
CAM = ReLU( Σ_k  α_k · A_k )
```

where `A_k` is the activation map of the k-th channel and `α_k` is its weight (the
global average of the corresponding gradient). The ReLU operation retains only the
regions that have a positive influence on the predicted class. The resulting CAM is a
single-channel spatial map that is normalised to [0, 1], upsampled to the original
image size (224 × 224) using bilinear interpolation, and overlaid on the CT image as
a colour heatmap using the **JET** colourmap. High-activation regions (shown in red)
correspond to the CT areas most influential for the prediction.

**Target layer selection.** The target convolutional layer is architecture-specific:

| Architecture | Target layer |
|---|---|
| EfficientNet-B0 | `model.backbone.conv_head` (final convolutional layer of the backbone) |
| DenseNet-121 | `model.backbone.features.denseblock4` (final dense block) |
| ResNet-50 | `model.backbone.layer4[-1]` (last residual block of the fourth stage) |

These layers represent the deepest convolutional activations before the global pooling
and classification head, and therefore capture the most semantically rich spatial
features.

**Hook mechanism.** Activations and gradients are captured using PyTorch **forward
and backward hooks** registered on the target layer. The forward hook saves the layer's
output tensor during the forward pass; the backward hook saves the gradient flowing
back through that layer during backpropagation. This mechanism requires no modification
to the model architecture.

> gradient pooling → weighted activation sum → ReLU → upsample → heatmap overlay

## 3.9 Evaluation Metrics

The following metrics are computed for each model and each dataset using the
`src/evaluation.py` module. All metrics are computed on the **held-out test set**,
which is used only once after training is complete.

**Accuracy** measures the overall proportion of correctly classified images:

```
Accuracy = (TP + TN) / (TP + TN + FP + FN)
```

**Precision** (Positive Predictive Value) measures the fraction of cancer predictions
that are correct:

```
Precision = TP / (TP + FP)
```

**Recall (Sensitivity)** measures the fraction of true cancer cases that the model
correctly identifies — the most clinically critical metric for a screening system:

```
Recall = TP / (TP + FN)
```

**Specificity** (True Negative Rate) measures the fraction of true benign cases
correctly identified:

```
Specificity = TN / (TN + FP)
```

**F1-Score** is the harmonic mean of precision and recall, providing a balanced
measure that is robust to class imbalance:

```
F1 = 2 × (Precision × Recall) / (Precision + Recall)
```

**ROC-AUC** (Area Under the Receiver Operating Characteristic Curve) summarises
model performance across all classification thresholds. An AUC of 1.0 indicates
perfect discrimination; 0.5 indicates no better than chance.

In addition, **confusion matrices** and **calibration curves** are produced for all
models. The calibration curve plots the mean predicted probability against the observed
fraction of positives across probability bins, indicating how well-calibrated the
model's confidence estimates are.

> **Table 3.7** — Evaluation metrics and their definitions

| Metric | Formula | Clinical significance |
|---|---|---|
| Accuracy | (TP+TN)/(TP+TN+FP+FN) | Overall correctness |
| Precision | TP/(TP+FP) | Reliability of cancer predictions |
| Recall (Sensitivity) | TP/(TP+FN) | Fraction of cancers detected (most critical) |
| Specificity | TN/(TN+FP) | Fraction of benign correctly identified |
| F1-Score | 2×P×R/(P+R) | Balance between precision and recall |
| ROC-AUC | Area under ROC curve | Overall discriminative ability |

## 3.10 Experimental Setup and Implementation Details

All experiments were conducted using **Python 3.9** with **PyTorch** (v2.x) as the
deep learning framework. The key libraries used are:

| Library | Role |
|---|---|
| `torch`, `torchvision` | Model construction, training and inference |
| `timm` | EfficientNet-B0 loading (pre-installed on Kaggle) |
| `pydicom` | DICOM loading and metadata extraction |
| `albumentations` | Classical augmentation pipeline |
| `xgboost` | XGBoost meta-learner |
| `scikit-learn` | Evaluation metrics and stratified splitting |
| `opencv-python` | Image loading, resizing and Grad-CAM overlay |
| `gradio` | Web demonstration application |
| `matplotlib`, `seaborn` | Result visualisation |

Training was performed on a GPU (Kaggle cloud environment, NVIDIA Tesla T4 or P100).
The random seed was fixed to 42 for all NumPy, Python and PyTorch operations to ensure
reproducibility. Early stopping checkpoints are saved to `checkpoints/` and the best
validation-loss checkpoint is loaded for final evaluation. All output plots (confusion
matrices, ROC curves, calibration curves, Grad-CAM heatmaps, comparison figures) are
saved to `outputs/`.

The GAN was trained for 150 epochs on the IQ-OTH/NCCD training images. For the
LIDC-IDRI dataset, GAN augmentation was not applied because the class distribution
was already approximately balanced (Table 3.2); class weights in the loss function
were sufficient to handle the residual imbalance.

## 3.11 Web Demonstration Application

A web-based demonstration application is implemented in `demo_app.py` using the
**Gradio** framework. The application allows a user to:

1. Upload a lung CT image in PNG, JPEG or DICOM format.
2. Select the base CNN model to use for prediction (EfficientNet-B0, DenseNet-121 or
   ResNet-50).
3. Receive a real-time prediction (Cancer / No Cancer) with a confidence score.
4. View the Grad-CAM heatmap overlaid on the input image, highlighting the regions
   that drove the prediction.

The application loads the trained model checkpoints from the `checkpoints/` directory
and runs inference entirely within the browser session. It is intended to demonstrate
the practical utility of the system and to illustrate the integrated explainability
output to non-technical users. The web interface is accessible locally at
`http://localhost:7860` after launching with `python demo_app.py`.
